  THE CREDIT ECONOMY — THREE LAYERS |  |  |  | 
Layer | Mechanic | Detail |  | Notes
Layer 1: Administrator Passive Income | Each Administrator generates 2 Cr/turn inherently. | Commercial Hub adds +1 Cr/turn bonus per Administrator within range. |  | Scales with organizational growth. Early game floor. Commercial Hub is an Admin multiplier, not a standalone generator.
Layer 2: Landing Zone Public Market | Any player can sell resources at the Landing Zone without a Transit Hub. | Rate: 3 resources = 1 Cr. Colony-wide cap: 15 resources/turn total. Layer 3: Territory Income via HQ | HQ generates +1 Cr per claimed hex per turn. | Both Outpost and HQ hexes count. Encourages territorial expansion as an economic strategy. |  | Negligible early (1-2 hexes). Significant mid-late game (6-8 hexes = 6-8 Cr/turn passively).
Transit Hub: Primary Trade Engine | Sell up to 10 resources/turn at 2:1 rate (2 resources = 1 Cr). | Expansion Module increases sell cap. Operations Director improves rate. Commercial Hub Diplomatic Suite further improves rate. |  | Main credit engine mid-to-late game. Only building enabling inter-player trades (via Trade Network module).

===== SHEET: Module Glossary =====
Module Type | Build Cost | Upkeep | Personnel | Repeatable | Standardized Effect | Available On
Efficiency Module | 6 Cr | 1 Cr / turn | — | Yes | Increases primary output or reduces operational costs of this building | All Resource Generators, Warehouse, Transit Hub, Vehicle Workshop (on Commercial Hub, Efficiency Module instead boosts the Administrator Credit bonus — see Buildings & Modules)
Redundant Systems | 6 Cr | 1 Cr / turn | — | Yes | Reduces negative effects from events, sabotage, or environmental hazards | All Resource Generators, Habitat Module, Power Conduit, Warehouse, Transit Hub, HQ, Vehicle Workshop
Expansion Module | 6 Min + 6 Cr | 1 E + 1 Cr / turn | — | Yes | Increases capacity, range, reach, or sell cap of this building's primary function | Power Facility, Water Reclamation, Habitat Module, Outpost, HQ, Power Conduit, Commercial Hub, Comms Array, Transit Hub, Vehicle Workshop
Fortification | 10 Min + 6 Cr | 1 E + 1 Cr / turn | +1 Contractor | Yes | Increases resistance to hostile unit actions and sabotage; requires security staffing | Outpost, Headquarters, Warehouse, Communications Array
Security Detail | 6 Min + 6 Cr | 1 E + 1 Cr / turn | +1 Contractor | — | Assigns Contractors to this building; protects against Analyst sabotage actions | All buildings except Power Conduit
Operations Director | 6 Cr | 1 Cr / turn | +1 Administrator | — | Assigns an Administrator; increases primary output or reduces upkeep of this building | All buildings except Power Conduit and Outpost
Terrain Exploit | 10 Min + 8 Cr | 1 E + 1 Cr / turn | +2 Engineer | — | Unlocks bonus output when built on the matching terrain hex type | Extraction Site, Water Reclamation
Sensor Array | 6 Cr + 3 Research | 1 E + 1 Cr / turn | +1 Analyst | — | Reveals information about adjacent hexes, rivals, or market activity; requires Analyst operator | Extraction Site, Commercial Hub, Outpost, Headquarters, Comms Array

===== SHEET: Action System Overview =====
RED PLANET CORPORATE — ACTION SYSTEM |  |  |  |  |  | 
Actions are divided into Building Actions and Unit Actions. Passive systems resolve automatically without player input. |  |  |  |  |  | 
  GARRISON PHASE  —  Declared at the start of every turn submission |  |  |  |  |  | 
Garrison Rules |  |  |  |  |  | 
• Each player explicitly assigns units to buildings before actions are declared. |  |  |  | Garrisoning has no cost. It is simply the act of assigning units to locations. |  | 
• Units not garrisoned are AVAILABLE and may take one Unit Action each this turn. |  |  |  | A garrisoned unit cannot take Unit Actions. It is occupied by the building. |  | 
• A building requires specific unit types to be fully garrisoned to function. |  |  |  | Meeting the minimum Engineer garrison enables resource production and Engineer-dependent building actions. |  | 
• Partial garrison enables only the actions supported by present unit types. |  |  |  | Example: Extraction Site needing 2 Eng + 1 Con with 2 Eng only → can harvest, cannot use Security Detail defense. |  | 
• A building with surplus garrison (e.g. 4 Engineers where 2 are required) can take |  |  |  | multiple actions of the same type per turn, consuming 1 full garrison set per action. |  |

===== SHEET: Vehicle Hull Classes =====
RED PLANET CORPORATE — VEHICLE SYSTEM |  |  |  |  |  | 
Vehicles are built at the Vehicle Workshop using a hull + module system, similar to building modules. Vehicles are crewed by existing personnel, not a separate unit type — they act as force multipliers. |  |  |  |  |  | 
  HULL CLASSES |  |  |  |  |  | 
Hull Class | Slots | Build Cost | Crew Req. | Upkeep | Role / Profile | Notes
Light | 2 | 8 Min + 6 Cr | 1 | 1 Cr / turn | Fast, cheap, single-purpose. Scouting, light escort, quick-response. | Best for early game or specialist roles. Can be produced quickly and in volume.
Medium | 4 | 16 Min + 12 Cr | 2 | 2 Cr / turn | Balanced workhorse. Hauling, patrol, multi-role field support. | The default general-purpose hull. Most flexible slot-to-cost ratio.

  CREWING RULES |  |  |  |  |  | 
Who can crew | Any existing personnel type (Engineer, Contractor, Administrator, Innovator, Analyst) may crew a vehicle. No new unit type is created. |  |  |  |  | 
Crew assignment | Crewing a vehicle is a Garrison-equivalent assignment — declared in the turn's Garrison Phase alongside building assignments. |  |  |  |  | 
Crewed unit status | A crewed unit is treated as AVAILABLE for action purposes, but acts through the vehicle. The vehicle's modules and hull determine what action the crew can take and how effective it is. |  |  |  |  | 
Module-crew matching | Most modules are most effective when crewed by their thematically matching personnel type (a Weapon Module crewed by a Contractor, a Sensor Module crewed by an Analyst) — see Module reference for specifics. Mismatched crew can still operate the vehicle, but does not receive the role bonus. |  |  |  |  | 
Vehicle loss | If a vehicle is destroyed or disabled in conflict, crew is NOT lost — they return to the available pool next turn, shaken but alive. Only the vehicle and its installed modules are lost. |  |  |  |  |

  MOVEMENT RULES |  |  |  |  |  | 
Rule | Detail |  |  |  |  | 
Base movement | All units may move to one adjacent hex per turn as part of declaring an action there. Movement is not a separate action. |  |  |  |  | 
Difficult terrain | Entering a Mountain or Rare Minerals hex consumes a unit's entire movement for the turn. A unit cannot enter difficult terrain and then continue to another hex in the same turn — it must stop and act there, or simply move there with no action. |  |  |  |  | 
Impassable terrain | Units cannot enter impassable hexes under any circumstances, including vehicles with Long-Range Propulsion. Pathing must route around. |  |  |  |  | 
Vehicle movement — standard | A crewed vehicle with no Mobility modules follows the same adjacency rules as its crew would on foot. |  |  |  |  | 
Vehicle movement — Upgraded Drivetrain | Grants 2-hex range per turn instead of 1. Does not override difficult terrain's movement-consuming effect. This is a flat range boost independent of the Transit Hub network. |  |  |  |  | 
Vehicle movement — Long-Range Propulsion | Grants a fixed extended radius of 4 hexes per turn. Independent of and stacks with Transit Hub network access if the vehicle also happens to be at a connected hub. |  |  |  |  | 
Landing Zone access | The Landing Zone is always freely accessible to all units regardless of borders, spotting risk, or territorial claims. It is neutral ground by design, and its permanent Transit Hub is the universal network anchor — see Transit Hub Network section below. |  |  |  |  | 
  TRANSIT HUB NETWORK |  |  |  |  |  | 
Element | Detail |  |  |  |  | 
What it is | Transit Hubs do not grant map-wide reach. Instead, each Transit Hub is a node. A unit located in the same hex as a connected Transit Hub may instantly jump to any other connected hub in that network and act from there this turn. |  |  |  |  | 
No garrison required | Transit Hub network access is structural, not personnel-based. A unit does not need to be assigned/garrisoned to the hub — simply being in that hex when declaring an action is enough to use the network. |  |  |  |  | 
Landing Zone anchor | The Landing Zone hosts a permanent Transit Hub that every subdivision can always use, regardless of network ownership. It is the one universal node every player's network effectively connects to. |  |  |  |  | 
Minimum network size | A single player-owned Transit Hub is already useful — combined with the Landing Zone hub, it forms a usable 2-node network from turn one of having any Transit Hub built. |  |  |  |  | 
Own network | All Transit Hubs owned by a single subdivision are automatically connected to each other and to the Landing Zone hub. A subdivision with 3 Transit Hubs has a 4-node network (3 own hubs + Landing Zone) that any unit can use freely from any one of those hexes. |  |  |  |  | 
Rival network access | A subdivision's Transit Hub network is private by default. Granting a rival access is a social/diplomatic outcome — typically the result of a Negotiate (Administrator unit action). No separate mechanic or cost is defined; the terms are whatever the two players agree to. |  |  |  |  | 
Revoking access | Since granted access has no formal mechanic, revoking it is equally informal — simply a matter of one player declaring the arrangement over. Players should expect this to be tracked socially, not by the host. |  |  |  |  | 
Vehicle use of network | Vehicles use the Transit Hub network exactly like personnel — if a vehicle is in a connected hub's hex, it may jump to any other connected hub. This stacks independently with any Mobility module range bonus the vehicle has for its non-network movement. |  |  |  |  | 
  CLOSED BORDERS & SPOTTING MECHANIC |  |  |  |  |  | 
Element | Detail |  |  |  |  | 
What "closed borders" means | A subdivision may declare its territory closed to a specific rival (or to all rivals) as a standing instruction to the host. Closed borders do not physically block movement — they activate the spotting mechanic on any unit that crosses without permission. |  |  |  |  | 
Base spotting chance | 20% chance per unit per turn that a unit moving through closed rival territory is spotted, checked by the host at the moment the action resolves. |  |  |  |  | 
Fortification modifier | Each Fortification module installed on a building in the territory adds +10% to the spotting chance for units passing through that hex or any hex adjacent to the fortified building. |  |  |  |  | 
Analyst modifier | Analyst units have a -10% modifier to their own spotting chance, reflecting their training in stealth and infiltration. This stacks with Fortification modifiers on the defending side — the two are calculated independently before combining. |  |  |  |  | 
Vehicle modifier | A vehicle entering closed territory uses the spotting chance of its crew's unit type, not a separate vehicle-specific roll. A vehicle crewed by an Analyst gets the Analyst's stealth modifier. |  |  |  |  | 
Transit Hub jumps and spotting | Jumping into a connected Transit Hub does not trigger a spotting check by itself — the network only connects a subdivision's own hubs and the Landing Zone, none of which require crossing closed rival territory. Spotting only applies to adjacency-based movement through a rival's claimed hexes. |  |  |  |  | 
On a successful crossing (not spotted) | The unit completes its action normally. The territory owner is not notified anything happened. |  |  |  |  | 
On being spotted | The unit is CAPTURED — immediately removed from play and held by the territory-owning subdivision. The unit does not take its declared action. The unit's owner is notified of the capture by the host. |  |  |  |  | 
Resolving a capture | A captured unit remains held until the two players negotiate a resolution directly — release, trade, ransom, or any other terms they agree to. The host does not impose a default resolution; this is intentionally left to player diplomacy. |  |  |  |  | 
No resolution reached | If no resolution is reached, the unit remains captured indefinitely. It does not count toward either subdivision's available personnel, Garrison, or scoring categories while held. |  |  |  |  |

===== SHEET: Dynamic Market System =====
RED PLANET CORPORATE — DYNAMIC RESOURCE MARKET |  |  |  |  | 
Replaces the flat Transit Hub/Landing Zone sell rates. One colony-wide market per resource, prices driven by aggregate player supply and demand each turn. Player-to-player trade always beats trading with Earth when both sides are present. |  |  |  |  | 
  BASELINE RESOURCE PRICES |  |  |  |  | 
Resource | Baseline Price (Cr/unit) | Reasoning |  |  | 
Energy | 0.5 Cr | High base production rate (+2/turn standard), cheapest to produce in volume — lowest baseline. |  |  | 
Minerals | 0.5 Cr | Also high-volume baseline production; primary construction material so demand is naturally constant. |  |  | 
Water | 0.75 Cr | Moderate production rate, dual-purpose (personnel + Bio Facility), slightly scarcer than Energy/Minerals. |  |  | 
Food/Bio | 0.75 Cr | Same tier as Water — essential, moderate production, steady demand from personnel upkeep. |  |  | 
Research | 1.5 Cr | Lowest production volume of any resource, gated behind Innovator-heavy investment — highest baseline value. |  |  | 
  PRICE MOVEMENT FORMULA |  |  |  |  | 
Element | Formula / Rule |  |  |  | 
Net Flow | Net Flow = Total units BOUGHT colony-wide this turn − Total units SOLD colony-wide this turn (per resource) |  |  |  | 
Price Shift | New Live Price = Current Live Price × (1 + (Net Flow ÷ 100) × 0.03), capped at ±15% movement in a single turn |  |  |  | 
Reversion | After the shift above is applied, the price moves 25% of the remaining distance back toward Baseline Price — this happens every turn regardless of trading activity |  |  |  | 
Price Floor/Ceiling | Live Price can never fall below 40% of Baseline or rise above 250% of Baseline, regardless of flow — prevents total market collapse or runaway hyperinflation on any single resource |  |  |  | 
Volatility tuning | The 0.03 coefficient and 25% reversion rate are tuned for MODERATE volatility — meaningful swings on heavy trading turns, but no single turn's activity can permanently break a resource's price. |  |  |  | 
  WORKED EXAMPLE — Minerals over 3 turns |  |  |  |  | 
Turn | Bought | Sold | Net Flow | Price Shift | Live Price (after reversion)
Start | — | — | — | — | 0.50 Cr (baseline)
Turn 1 | 20 | 60 | -40 | 0.50 × (1 - 0.012) = 0.494 | 0.494 + 25% toward 0.50 = 0.4955 Cr
Turn 2 | 15 | 80 | -65 | 0.4955 × (1 - 0.0195) = 0.4859 | 0.4859 + 25% toward 0.50 = 0.4894 Cr
Turn 3 | 70 | 10 | +60 | 0.4894 × (1 + 0.018) = 0.4982 | 0.4982 + 25% toward 0.50 = 0.4987 Cr
  EARTH TRADE vs. PEER-TO-PEER TRADE |  |  |  |  | 
Scenario | Resolution |  |  |  | Trade Type
Selling — no buyer present | Routes to Earth via Landing Zone. Seller receives Live Price × 0.80 (20% export discount) per unit. |  |  |  | EARTH SALE
Selling — a buyer IS present | Matches directly with the buying player(s) at full Live Price, no discount. If multiple buyers compete for limited supply, host allocates proportionally or by player preference order stated in submissions. |  |  |  | PEER TRADE
Buying — no resupply mission active and no seller present | Cannot buy that resource this turn — there is no supply source. |  |  |  | UNAVAILABLE
Buying — resupply mission active, no seller present | Buyer pays Live Price × 1.20 (20% import markup) per unit, up to the resupply mission's available quantity. |  |  |  | EARTH PURCHASE
Buying — a seller IS present (regardless of resupply status) | Buyer pays full Live Price to the selling player — always cheaper than the resupply markup, so peer trade is preferred whenever available. |  |  |  | PEER TRADE
Buying — both resupply AND a seller present | Buyer should default to the peer seller (better price) unless the player specifically prefers Earth sourcing for narrative/strategic reasons (e.g. avoiding visible dependency on a specific rival). |  |  |  | PLAYER CHOICE
  EARTH RESUPPLY MISSIONS |  |  |  |  | 
Element | Detail |  |  |  | 
Cadence | Host discretion / narrative-driven. No fixed schedule — resupply missions arrive when the host determines it fits the story (a scheduled cargo run, an emergency drop, a corporate logistics announcement). |  |  |  | 
Quantity | Host sets per mission based on narrative context — a routine resupply might bring a modest amount of one or two resources; a major one could refill several. |  |  |  | 
Announcement | Resupply missions are announced publicly (Landing Zone activity is observable to all) at least the turn before or the turn they arrive, giving players a window to plan purchases. |  |  |  | 
Interaction with Market Sale/Trade Network | Resupply purchases happen through the same Trade Action (Administrator unit action) used for all other market activity — no separate action type needed. |  |  |  | 


===== SHEET: Subdivision Equity Market =====
SUBDIVISION EQUITY MARKET |  |  |  |  | 
Each subdivision has tradeable shares. Price is anchored to Composite Score. Owning shares pays a dividend tied to the issuing subdivision's Economic category score. |  |  |  |  | 
  SHARE BASICS |  |  |  |  | 
Element | Detail |  |  |  | 
Shares per subdivision | 100 shares issued at game start, fixed — does not change over time. |  |  |  | 
Starting price | 10 Cr/share for every subdivision at game start, regardless of parent company — all start equal. |  |  |  | 
Who can buy | Any player may buy shares in any subdivision, including their own (though buying your own shares has limited strategic value beyond price support). |  |  |  | 
How shares are bought/sold | Through the Trade Action (Administrator unit action) as a sub-action, alongside resource market activity. |  |  |  | 
  SHARE PRICE FORMULA |  |  |  |  | 
Element | Detail |  |  |  | 
Anchor | Share Price = (Composite Score ÷ 10) + 5, recalculated each turn after scoring is updated (Phase 8 of turn processing). |  |  |  | 
Trading pressure | Net buy/sell pressure on a subdivision's shares this turn shifts the price an additional ±5% per 10 net shares traded, same volatility logic as the resource market, capped at ±15%/turn. |  |  |  | 
Floor | Share price can never fall below 1 Cr/share, regardless of performance or trading pressure — total wipeout isn't possible, only severe devaluation. |  |  |  | 
Worked example | A subdivision with Composite Score 56.5 has an anchor price of 10.65 Cr/share before trading pressure is applied that turn. |  |  |  | 
  DIVIDENDS |  |  |  |  | 
Element | Detail |  |  |  | 
Formula | Each turn, the issuing subdivision pays Total Dividend = Economic Category Score ÷ 20 (in Credits), split proportionally among all shareholders based on shares owned. |  |  |  | 
Who pays | The dividend is paid BY the issuing subdivision FROM their own Credits — it is a real cost to the subdivision being invested in, not free money created by the system. |  |  |  | 
Strategic implication | A subdivision with a strong Economic score is an attractive investment (pays well) but also bleeds Credits to shareholders every turn — a subdivision with many of its own shares bought back by rivals is effectively subsidizing their opponents. |  |  |  | 
Worked example | A subdivision with Economic Score 22 pays 1.1 Cr total dividend this turn, split among shareholders — if a rival owns 30 of their 100 shares, that rival receives 0.33 Cr this turn. |  |  |  | 
  STRATEGIC USES — "Economic Warfare" |  |  |  |  | 
Tactic | Effect |  |  |  | 
Buying a rival's shares | Signals confidence (or simply extracts dividend value from a strong economic performer) — a quiet way to benefit from a rival's success without cooperating with them directly. |  |  |  | 
Mass-selling a rival's shares | Crashes their share price via trading pressure, which has no direct mechanical effect on the issuing subdivision's own resources/score, but is a visible public signal of distress or attack — purely reputational/social pressure, no hard mechanical teeth. |  |  |  | 
Buying back your own shares | Removes them from rival hands (reducing dividend bleed to opponents) and provides modest price support — a defensive economic move for a subdivision being targeted. |  |  |  | 
No hostile takeover mechanic | Owning a majority of a rival's shares does NOT grant any control, intel, or special access to that subdivision — equity is purely financial, never operational. This keeps the equity market from becoming a backdoor way to attack a subdivision's actual infrastructure. |  |  |  | 


===== SHEET: Scoring System =====
RED PLANET CORPORATE — SCORING & STANDINGS |  |  |  |  | 
Rolling standings, updated every turn, with no formal game end. Six category scores plus a weighted composite overall score. Earth Relations is tracked separately and does not factor into scoring. |  |  |  |  | 
  SIX SCORING CATEGORIES |  |  |  |  | 
Category | Linked Unit | Formula (per turn snapshot) | Weight |  | 
Economic | Administrator | Current Credits stockpile + (cumulative Credits earned via Market Sale and Amplify Credit Yield this season ÷ 10) |  |  | 1.0x
Industrial | Engineer | Sum of current Energy + Minerals + Water + Food/Bio stockpiles ÷ 4, plus +1 per active Resource Generator building |  |  | 1.0x
Research | Innovator | Cumulative Research generated this season + (2 × number of completed research submissions) |  |  | 1.0x
Territorial | Engineer / Contractor | Number of claimed hexes × 2, + 3 per Headquarters held, + 1 per Outpost held |  |  | 1.0x
Security | Contractor | Successful Sabotage defenses this season × 2, + successful Intercepts × 2, + Fortification/Security Detail modules installed |  |  | 0.75x
Intelligence | Analyst | Successful Sabotage/Surveillance actions this season × 2, + undetected Plant Intel actions × 3 |  |  | 0.75x
  COMPOSITE OVERALL SCORE |  |  |  |  | 
Formula | Sum of all six weighted category scores = Composite Score |  |  |  | 
Security & Intelligence Weight | 0.75x — these categories have a defensive/reactive component that depends partly on rival behavior, not pure subdivision output, so they're weighted slightly below the four primarily self-driven categories |  |  |  | 
Normalization | Host may normalize scores across the colony periodically (e.g. every 10 turns) so that early-game small numbers don't permanently disadvantage late-blooming subdivisions |  |  |  | 
Display | Public colony dashboard shows: Composite Rank (1st–Nth), plus each subdivision's best category ("Leading in: Research") |  |  |  | 
  CATEGORY LEADERBOARD  —  Bragging rights independent of composite rank |  |  |  |  | 
Per-Category Leader | The subdivision with the highest raw score in each of the six categories is recognized as that category's current leader, regardless of overall composite rank |  |  |  | 
Title | Category leaders receive an in-fiction title for flavor — e.g. "Economic Leader," "Research Leader" — purely cosmetic, no mechanical bonus |  |  |  | 
Multiple Leaders | A subdivision can lead multiple categories simultaneously. A subdivision leading 3+ categories simultaneously may be informally recognized as the season's dominant player even if composite rank doesn't reflect it cleanly |  |  |  | 
Volatility | Category leadership can change turn to turn — this is intentional. It keeps every category relevant and contestable throughout the game rather than settling into a permanent hierarchy |  |  |  | 
  SEASONAL CHECKPOINTS  (optional — informal, no hard reset) |  |  |  |  | 
What it is | Every 10-15 turns, the host can post a "checkpoint" summary recognizing the current composite leader and each category leader at that moment in time |  |  |  | 
Mechanical effect | None — purely a narrative/social checkpoint. Standings continue rolling afterward with no reset |  |  |  | 
Why include it | Gives the ongoing game natural narrative beats and recognition moments without forcing a hard end or disrupting the rolling standings model |  |  |  |

===== SHEET: Turn Structure =====
RED PLANET CORPORATE — TURN STRUCTURE & PROCESSING ORDER |  |  |  |  | 
Submission window length is flexible, set by host discretion based on player engagement and pacing. The processing order below is fixed regardless of window length. |  |  |  |  | 
  PROCESSING ORDER — 8 PHASES |  |  |  |  | 
Phase | Name | What Happens | Timing Note |  | 
1 | Submission Window | All players submit their turn privately to the host using the Turn Submission Template — Garrison, Building Actions, Unit Actions, Political Action, Corporate Action, Notes. |  | Window length is host discretion. Late submissions default to 'repeat last turn's garrison, no new actions' unless host rules otherwise. | 
2 | Simultaneous Resolution Check | Host reviews all submissions together for anything requiring cross-reference before processing: matching trade terms, contested hex claims, multiple units acting in the same hex, Intercept targets. |  | This is a read-through pass, not yet applying effects. Identifies what needs discretionary judgment in later phases. | 
3 | Passive Systems | Resource generation (for buildings meeting minimum garrison), building upkeep, personnel upkeep, Administrator passive income, territory income, Research accumulation, colonist arrivals scheduled for this turn. |  | Fully automatic — no discretion required. Pure arithmetic from current state. | 
4 | Building Actions | All declared Building Actions resolve — Harvest, Boost Output, Market Sale, Colonist Requisition, Passive Intel Scan, etc. Requires the building's garrison to meet personnel requirements as declared in Phase 1. |  | A building completed THIS turn cannot take building actions this turn — see Construction Timing below. | 
5 | Unit Actions | All declared Unit Actions resolve simultaneously — Construct, Survey, Sabotage, Patrol, Trade Action, Field Research, etc. Movement (adjacency, Transit Hub network, vehicle range) is resolved as part of each action. |  | Simultaneous by default. Direct conflicts (two units acting on the same target, an Intercept vs. its target action) are resolved at host discretion based on investment differential, per the Conflict Resolution framework. | 
6 | Political & Corporate Actions | Each subdivision's single Political Action and single Corporate Action (if declared) resolve. Votes are tallied if an active Motion exists. Company-specific bonuses applied. |  | Processed after Unit Actions so that any newly-changed state (new buildings, captured units) is reflected before political/corporate effects apply. | 
7 | Event Roll | Host rolls for a random event (15% base chance). If triggered, rolls scope (Colony-wide/Regional/Subdivision) and tone (Hazard/Opportunity/Neutral), applies the result. |  | Always after actions — events react to what players did this turn (risk-weighted targeting), not the reverse. | 
8 | Reporting | Host updates tracked values (Earth Relations per subdivision, scoring categories, Research pools), posts the public standings dashboard, posts any public statements/broadcasts, and sends each player their private turn report. |  | Public vs. private split per the Information Visibility rules below. | 
  CONSTRUCTION TIMING — Buildings, Modules, Vehicles |  |  |  |  | 
Rule | Detail |  |  |  | 
General rule | Anything built (building, module, tier upgrade, vehicle) takes a minimum of 1 turn to construct. It is not active, cannot be garrisoned, and cannot take or enable any action until the turn AFTER the turn the build action was declared. |  |  |  | 
1-turn builds | Standard buildings, modules, and vehicles complete in 1 turn: declared in Turn N, active starting Turn N+1. |  |  |  | 
Multi-turn builds | If a future building/module/vehicle is defined with a longer build time (e.g. 2 turns), it follows the same logic generalized: declared in Turn N, active starting Turn N+(build time). No exceptions. |  |  |  | 
Garrison before completion | A player may declare garrison assignments to a building that will complete next turn as part of THIS turn's submission, but those units remain in their previous state (available or garrisoned elsewhere) until the building actually exists. The garrison declaration simply takes effect automatically the turn the building completes, so the player doesn't need to remember to re-declare it. |  |  |  | 
Vehicles | Same rule applies. A vehicle ordered via Produce Vehicle (building action) is not available for crewing or action until the turn after production completes. |  |  |  | 
  SIMULTANEOUS ACTIONS & DISCRETIONARY CONFLICTS |  |  |  |  | 
Element | Detail |  |  |  | 
Default assumption | All unit actions across all players are treated as happening simultaneously within a turn. There is no submission-order advantage — submitting early does not grant priority. |  |  |  | 
When this breaks down | Some actions are inherently about one player acting on another (Sabotage, Intercept, Enforce Territory, spotting checks). These require host judgment rather than pure simultaneous resolution. |  |  |  | 
Host's approach | Per the Conflict Resolution framework — compare relevant investment (unit count, modules, Fortification/Security Detail stacks) on each side. Large differentials resolve deterministically in favor of the stronger side. Close differentials get a minor random element. |  |  |  | 
Two units, same target, same effect | If two unrelated players both target the same building with conflicting actions in the same turn (e.g. both Sabotage the same Extraction Site), the host resolves each independently against the defender's investment — both could succeed, both could fail, or one of each, depending on the defender's total capacity to respond to multiple threats. |  |  |  | 
Host discretion is final | Genuinely ambiguous edge cases are resolved by host judgment in the spirit of internal consistency and fairness, not a rigid priority algorithm. This keeps the system flexible enough to handle situations the rules didn't anticipate. |  |  |  | 


===== SHEET: Information Visibility =====
INFORMATION VISIBILITY — Public vs. Private by Default |  |  |  | 
General principle: information that would logically be common knowledge on a shared colony is public. Information that would logically be private corporate/operational data is hidden by default. |  |  |  | 
Information Type | Default | Reasoning | Can Change Via | Notes
Composite score & category rankings | PUBLIC | The standings dashboard is the whole point of public competition — everyone can see relative performance. | — | Posted every turn in the Reporting phase.
Category leaders | PUBLIC | Bragging rights only have value if visible. | — | Cosmetic titles, no mechanical effect.
Building locations & types (visible on map) | PUBLIC | A building is a physical structure on a shared map — its existence and general type are observable to anyone with map access, like satellite imagery. | — | What's hidden is the building's INTERIOR state — garrison, exact production, modules — not its existence.
Claimed hex ownership | PUBLIC | Territorial claims are inherently a public-facing assertion on the shared colony map. | — | Closed border STATUS may be public, but doesn't reveal what's happening behind it.
Exact resource stockpiles | PRIVATE | Corporate financials are confidential by nature — this is the core resource you're managing strategically. | Corporate Audit (forces reveal), Sensor Array Market Surveillance, Trade negotiations | Revealed only through specific intel actions or by choice (negotiating a trade requires some disclosure).
Garrison assignments | PRIVATE | Personnel deployment is operational security — revealing exactly how many Engineers staff which building gives rivals targeting information. | Successful Patrol, Enhanced Surveillance, Field Surveillance unit actions | Partial reveal only — these actions return limited detail per their definitions, not full garrison lists.
Earth Relations score | PRIVATE | Per-subdivision and tied to internal performance — not a colony standing, a corporate relationship metric. | Never automatically revealed | Entirely the subdivision's own business unless they choose to disclose it socially.
Module installations | PRIVATE (mostly) | Detailed loadout is operational info, though a building's overall tier/silhouette might be visually inferable. | Enhanced Surveillance, Corporate Audit | Host's call on how much a casual observer could plausibly infer vs. what requires dedicated intel-gathering.
Research in progress / completed | PRIVATE until shared | Research is explicitly framed as proprietary IP — the whole incentive of Research Sharing for Earth Relations only works if it's normally private. | Research Sharing Political Action (voluntary disclosure to Earth, not necessarily to rivals), Diplomatic Suite Research Complex agreement | Submitting to Earth for Relations doesn't automatically make it public to rivals unless the player also broadcasts it.
Public Statements / Broadcasts | PUBLIC | By definition — that's the entire purpose of the action. | — | Content is whatever the player submits; host posts as-is (in-character).
Denouncements | PUBLIC | An accusation only has social weight if the colony can see it. | — | Both the accusation and (if applicable) the target's response/silence are visible.
Formal Agreements (Form Agreement) | PUBLIC | Per the diplomatic framework — these are announcements with social but not mechanical weight, so visibility is what gives them any teeth at all. | — | No enforcement mechanism; visibility is the only consequence structure for breaking one.
Captured units (from spotting) | PRIVATE between the two parties involved | Not a colony-wide announcement — it's a direct incident between the capturer and the captured subdivision. | Either player can choose to disclose it publicly | Host notifies only the two subdivisions involved per the Movement & Borders rules.
Vehicle designs (modules installed) | PRIVATE | Same logic as building modules — loadout is operational info even if the vehicle's existence/hull class might be observable. | Surveillance-type unit actions, direct combat encounter | A vehicle's presence in a hex may be visible; its loadout generally is not without investigation.
Active colony Motions (Propose Motion) | PUBLIC | A vote requires the colony to know what's being voted on. | — | Individual vote choices (per Vote on Motion) may remain private unless a player chooses to disclose their vote.
